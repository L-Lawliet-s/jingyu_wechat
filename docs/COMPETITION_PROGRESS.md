### 使用及实测路径

1. 从源码更新，安装已有项目开发依赖后执行 `npm.cmd run desktop:build`，打开 `WeChatAgent.exe`，选择“晚饭与晚间安排”。
2. 先点击“试用演示”并创建任务。确认一份餐品后，手机或桌面把预算从 30 元改为 20 元，查看旧选择清空与新比较结果，重新选餐后走完演示核对和反馈。
3. 手机测试时，手机与电脑连接同一可信 Wi-Fi。电脑点击“连接手机 → 开启手机配对”，手机浏览器输入显示的局域网地址及一次性配对码。页面打不开时先检查所选网卡、Windows 私有网络入站规则和 Wi-Fi 是否启用了设备隔离。能看见同一任务和版本后再开始真实测试。
4. 真实任务任选一个平台，手动在其页面准备登录和配送地址。录入至少 2–3 个真实餐品及可见费用，核对来源与时间。记录可读控件为多少、是否自动加购成功、是否由本人手工接管。
5. 在平台确认餐品规格与份数，回小鲸鱼填写实付报价和预计送达。用户自行处理点餐后标记结果，用餐后填反馈。验证下一次按同一口味比选，以及清除偏好后的恢复。
6. 先用物理手机和单平台购物车完成一次验收，再测第二平台。将任务设备、平台、状态、时延、失败原因和脱敏截图补入本报告。正式材料视赛区要求匿名整理。

## 2026-11-16 · 第三步 生活琐事、日程与个人节奏

| 实现功能 | 如何实现 |
| --- | --- |

| 通知来源与撤回 | 保存的事项记录来源类别及历次修改。原通知摘录仅在用户勾选时保存，单独存储，用户可删除摘录并保留事项。两端列表只返回摘要，打开事项才读取已保存的摘录。 |
| 冲突、改期和同地点连排 | 开始时间、预计耗时和截止时间先校验，再和已录入日历或事项比较。用户可改期或确认保留冲突。同地点、暂无开始时间的事项可生成连续安排，明确确认后在一个 SQLite 事务内保存，逐条保留截止时间、状态和完成反馈。修改按版本校验，旧版本和被抢占的空档会提示同步。 |
| 应用提醒与系统日历 | 生活日程页面显示到时提醒，使用阶段二的提醒个性卡、暂停及北京时间安静时段。支持已读、暂停、恢复、推迟约 15 分钟。进行中且已有开始时间的事项可以导出含提醒的 `.ics`，导入的 `.ics` 用作冲突检查的日历快照。 [iCalendar RFC 5545](https://www.rfc-editor.org/rfc/rfc5545.html) |
| 个人节奏、反馈和休息 | 手填精力、任务压力与可用时长，状态 8 小时失效并可主动清除。建议按日历空档、时长和截止时间生成。休息建议会参考最近一周内最近一次评为有帮助的休息时长。选择采纳后可核对并保存，完成时记录是否有帮助和用时。每日回顾模式展示当天已完成事项。可主动看 B 站热门和评论，复用既有 B 站只读模块。 |

主要实现位于 `packages/jingyu/life.mjs`、`life-calendar.mjs`、`life-ocr.mjs` 和 `public/console/life-ui.js`。新增测试位于 `scripts/test-life.mjs`。日程和截图请求沿用本机令牌和手机配对校验。

### 真机验收

## 2026-11-16 · 第五步 短途出行与微信多人协作

### 微信演示步骤

1. 在「鲸鱼账户与记忆」核对主人微信 ID。把同意试用的联系人加入私聊允许范围，保存后重启鲸鱼服务以重新加载微信桥。
2. 发起人对小鲸鱼发「出游新建 周六看展」。将回信中的「出游 活动码 加入」发给同行者。同行者将该句私聊发给小鲸鱼。
3. 发起人和同行者分别发「出游 活动码 周六10:00到16:00，预算200元，偏好室内看展」。收到草稿后各自发送原样的「出游 活动码 确认 1」或消息里给出的确认号。预算按人均上限解释。
4. 发起人发「出游 活动码 汇总」，核对条件。可在桌面增添室内、户外备选，也可在微信发「出游 活动码 方案 博物馆｜博物馆东门｜2026-11-21 10:00｜2026-11-21 14:00｜80｜0｜室内」。再次汇总后按回复中的版本号发布。
5. 同行者发「出游 活动码 查看」。发起人可在桌面记录雨雪或预约不可用，或私聊发「出游 活动码 下雨」。同行者重新查询将看到变化提示。发起人核对并重新发布后，同伴可认领分工或发送反馈。发起人可在桌面导出日历。
