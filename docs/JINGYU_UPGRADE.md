# 鲸鱼源码升级流程

制定于 2026-10-26。开发仓库 `https://github.com/L-Lawliet-s/jingyu_wechat.git`；开发目录 `D:\code\jingyu_wechat`。现有 `D:\code\jingyu_runtime` 继续独立，不直接覆盖运行中的程序或账号数据。

## 交付顺序

1. 导入上游与来源许可，建立可回滚基线。
2. 增加原生余额设置、页面显示、聊天查询；凭据不交给模型，失败不当零余额。
3. 增加共享记忆服务与管理页：主人公开记忆跨聊天，其他人的私聊按真实联系人隔离；权限在检索前过滤。
4. 复用 DSH 管理员任务，增加按联系人、工作日与时段执行的学习提醒；保持持久化、取消与去重。
5. 增加异步微信动作管理与 Windows 驱动：拍一拍、语音发送、语音和视频呼叫；未验证的设备能力不能假报可用。
6. 增加外卖/视频任务入口，明确平台、订单确认、执行状态；优先复用已授权 DSH 工具。
7. 完成单元与集成验证、界面检查、构建和迁移说明，提交到本仓库。

## 架构原则

功能直接放入源码模块和现有桌面页面，不要求另装四个业务 ZIP。DSH 桥接仍作为程序内部运行组件保留。

新增设置、凭据、记忆、动作账本属于本机数据，默认位于当前工作区 state 下；凭据使用 Windows 当前用户加密，聊天和公开提交不包含原文密钥。

共享规则：与你聊天可读你的共享/私有记忆；与 A 聊天可读你的共享记忆及 A 的私有记忆；与 B 聊天可读你的共享记忆及 B 的私有记忆。只有可信主人来源可写主人记忆，别人自称主人或引用主人发言不能获得权限。撤销共享后也要让旧上下文失效。

## 验证边界

开发测试使用虚构账号、模拟 API 和临时工作区。真实发微信消息、拨号、订单提交不属于自动测试；需要明确目标和具体动作才能现场验收。不能把返回 accepted、生成 MP3、发出 HTTP 请求当成真实语音/呼叫成功。

与客户端、音频设备和账号登录相关的能力按实际探测声明，保留明确失败和人工接管路径。不得将空接口或无法执行的工具标成已完成。

## Git 流程

origin 指向用户仓库，upstream 保留只读来源用于比对。按完成的功能单独提交；不改写已推送历史，不提交运行数据或复制已有秘密配置。每个阶段记录实际测试与剩余设备验收。
