# 鲸鱼源码升级流程

制定于 2026-10-26。开发仓库 `https://github.com/L-Lawliet-s/jingyu_wechat.git`；开发目录 `D:\code\jingyu_wechat`。现有 `D:\code\jingyu_runtime` 继续独立，不直接覆盖运行中的程序或账号数据。

## 交付顺序

1. 导入上游与来源许可，建立可回滚基线。
2. 增加原生余额设置、页面显示、聊天查询；凭据不交给模型，失败不当零余额。
3. 增加共享记忆服务与管理页：主人公开记忆跨聊天，其他人的私聊按真实联系人隔离；权限在检索前过滤。
4. 复用 DSH 管理员任务，增加按联系人、工作日与时段执行的学习提醒；保持持久化、取消与去重。
5. 增加异步微信动作管理与 Windows 驱动：拍一拍、语音发送、语音和视频呼叫；未验证的设备能力不能假报可用。
6. 增加外卖/视频任务入口，明确平台、订单确认、执行状态；优先复用已授权 DSH 工具。
7. 完成单元与集成验证、界面检查、构建和迁移说明，提交到本仓库。

## 架构原则

功能直接放入源码模块和现有桌面页面，不要求另装四个业务 ZIP。DSH 桥接仍作为程序内部运行组件保留。

用户补充的实施目标：语音和视频接通后由小鲸鱼实时说话；外卖优先美团与淘宝，视频优先 B 站。

新增设置、凭据、记忆、动作账本属于本机数据，默认位于当前工作区 state 下；凭据使用 Windows 当前用户加密，聊天和公开提交不包含原文密钥。

共享规则：与你聊天可读你的共享/私有记忆；与 A 聊天可读你的共享记忆及 A 的私有记忆；与 B 聊天可读你的共享记忆及 B 的私有记忆。只有可信主人来源可写主人记忆，别人自称主人或引用主人发言不能获得权限。撤销共享后也要让旧上下文失效。

## 验证边界

开发测试使用虚构账号、模拟 API 和临时工作区。真实发微信消息、拨号、订单提交不属于自动测试；需要明确目标和具体动作才能现场验收。不能把返回 accepted、生成 MP3、发出 HTTP 请求当成真实语音/呼叫成功。

与客户端、音频设备和账号登录相关的能力按实际探测声明，保留明确失败和人工接管路径。不得将空接口或无法执行的工具标成已完成。

## Git 流程

origin 指向用户仓库，upstream 保留只读来源用于比对。按完成的功能单独提交；不改写已推送历史，不提交运行数据或复制已有秘密配置。每个阶段记录实际测试与剩余设备验收。

### P3：拍一拍、原生语音消息与拨号

2026-10-26 的本机只读检查中，微信 4.1.10.27 的控件树只提供窗口和窗格，没有提供可稳定定位的通话按钮。上游发送覆盖层目前实现文本、表情和文件，不能据此声称支持拍一拍、原生语音或电话。

按以下次序开发：

1. 为现有版本建立独立适配模块及只读能力检测，首先查明原生调用入口与需要的参数；不能拿其他版本的地址直接使用。
2. 若采用桌面操作，先验证截图识别方案，建立分辨率、缩放、窗口遮挡、聊天标题和联系人唯一性校验。界面不可读、目标有歧义或用户切换聊天时停止，不能固定坐标盲点。
3. 拍一拍只作用于已经验证的当前联系人。发送后从读取端确认对应系统消息，无法确认则标“结果未知”。
4. 原生语音需要明确选择“录音 UI 注入”或“该版本原生语音发送入口”，处理时长、编码和发送完成回执。普通 WAV/MP3 附件只能标为音频文件。
5. 拨号、接听、挂断分别实现，限定已允许联系人；重启后不能自动重拨。语音与视频分别探测，不能根据语音按钮存在就宣布视频可用。
6. 新增独立动作账本，状态包含排队、执行、等待接听、已连接、结束、失败、结果未知及取消。接收动作、目标核验、外部调用和回执确认分开记录；重复请求不能重复拨号或重复发语音。

阶段验收需由主人指定测试联系人和具体动作，再现场验证。当前没有向任何联系人发送测试消息、拍一拍或电话。

### P4：接通后由小鲸鱼自己说话

目标不是代你拨号。语音与视频通话接通后，模型应自己听、自己回答，并沿用对应联系人的人格和允许读取的记忆。

1. 先在本地完成 Vosk + Windows SAPI + DeepSeek 的实际耳机测试，测量识别错误、静音结束判定与响应延迟。
2. 配置两条独立虚拟音频通道；明确微信扬声器、微信麦克风、识别输入与合成输出的对应关系。只检测设备存在不足以证明路由正确，必须用实际声音验证。
3. 从微信读取/适配层确认通话真实连接状态后才启动 AI，不靠固定等待若干秒推测接通。拒接、超时或挂断后停止采音和模型请求。
4. 将当前音频测试中的主人固定身份改为通话目标的可信身份；每个目标单独上下文，沿用 P1 的权限过滤，不允许联系人之间混用记忆。
5. 从轮流听说升级为语音活动检测、对方插话打断、回声处理、增量识别和分段发声；网络中断或余额不足时只提示一次并停止。
6. 视频电话先实现正确拨号、连接与音频互动。若需要小鲸鱼可见画面，再接虚拟摄像头与小鲸鱼立绘/口型；没有配置时明确显示“未配置视频画面”。理解对方摄像头内容属于独立视觉功能，不能由接通视频推断已实现。
7. 默认通话时限与轮数限制保留，提供桌面立即停止、按联系人的允许时段与通话记录。通话不自动写长期记忆，主人显式要求记住后才按原规则保存。

本地 ASR/TTS 作为优先省费用方案，声音自然度和识别质量不作未经测试的承诺；后续可替换更自然的本地模型，保留同样接口。

### P5：美团、淘宝与 B 站

由主人的管理员任务触发，复用原有任务列表、进度、取消和结果通知。普通联系人聊天不获得电脑或购物账号操作权限。浏览器登录状态放在本机专用目录，不进入共享记忆或 Git。

| 平台 | 第一批动作 | 实现顺序与结果证据 |
| --- | --- | --- |
| 美团 | 搜索餐品、查看可配送商家、筛选预算、整理购物车 | 先实测登录后的可用入口；网页版无法完成时评估微信小程序或 Android 适配。结果回传餐品、店铺、实付、运费和预计送达；不能把搜索链接称为订单 |
| 淘宝 | 商品检索/比价、购物车；淘宝内外卖入口另作流程 | 按购物和外卖分开适配，以实际可用页面为准。先填写偏好及预算，再核验规格、地址、价格和配送；不得凭模型生成订单号 |
| B站 | 搜索、打开视频、播放/暂停、进度与音量、下一条 | 先做浏览器专用页面操作，再做播放状态检测；自动连续播放有时限和停止按钮。网页文字摘要与真实视频/字幕理解分别标记 |

所有订单先给出可确认的购物车与最终费用，付款和订单提交单独处理。登录、验证码和页面变更出现时让任务停在可恢复状态。未确认的请求不能重复下单。点赞、收藏、投币、关注等行为不作为“刷视频”的默认动作。

电脑任务先沿用上游已授权的助手模式；浏览器操作器的固定动作由宿主实现，模型提出目标和参数。不能直接把网页文字当成系统命令或授权。

### P6：迁移与发布

先对新旧数据做只读清单和备份，再将已确认归属的主人记忆、联系人私有记忆和定时任务分别导入。无法确定作者的旧笔记进入待审，不直接全局共享。

完整安装包必须包含新原生模块、音频工作进程及依赖说明。模型和第三方微信组件按各自的获取与许可条件处理。升级演练包含账号切换、旧数据恢复、发出请求后崩溃、设备失效、API Key 撤销、共享撤销和任务取消。通过后再用用户仓库发布 Release，保留旧运行版回退入口。
