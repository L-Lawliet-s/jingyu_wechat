# 自动聊天记忆

更新日期：2026-10-27。

## 使用效果

不需要先在软件里填写，也不需要在每句话前说“记住”。聊天被本项目接收后，会在处理对话时自动形成可检索的原话资料。

| 例子 | 可以知道的人 |
| --- | --- |
| 主人说“我在写论文” | 主人与其他已允许私聊 |
| 小张说“我今天吃了米饭” | 小张与主人 |
| 小李说“我今天吃了面条” | 小李与主人 |
| 主人说“【私密】我在准备一个惊喜” | 主人 |

主人可以询问“小张吃了什么”，联系人之间无法借用主人的权限查询彼此。昵称叫“主人”、在正文自称主人、引用主人发言均不会改变权限。群聊仍只使用手动发布并允许用于群聊的主人笔记。

## 怎么启用

1. 先完成微信连接验证，把要处理的私聊加入允许范围。
2. 在“鲸鱼账户与记忆”绑定主人的真实微信 ID，保留自动聊天记忆和主人分享开关。
3. DSH 必须启用当前项目 `packages/dsh-social-bridge-plugin`。从旧运行目录切换过来时，停用旧插件并添加当前目录，从托盘完整退出再重新打开 DSH。
4. 保存设置并启动服务。正常聊天即可；页面“自动聊天记忆”会显示来源人物、原话与时间。

当前开发目录为 `D:\code\jingyu_wechat`。如果 DSH 健康检查仍指向 `D:\code\jingyu_runtime\data\workspace`，必须先完成第 3 步，否则修改后的记忆逻辑不会加载。

## 记忆来源与范围

- 从同一个已验证微信账号的本机聊天档案读取，检索前按真实身份限制范围。
- 只索引已允许私聊中本人发来的文字。AI 回复、转发、引用、系统交互、任务模式的独立档案、原生模型草稿不加入自动跨聊天资料。
- 主人聊天中的 AI 回复可能已经引用其他联系人，因此不再次向外共享。这可以避免“小张 → 主人回复 → 小李”的信息扩散。
- 首次启用每个允许私聊导入最近 200 条已有档案；以后按游标每批至多 200 条持续追上新消息。超过一批的积压会在后续对话或记忆检索时继续处理。
- 每条原话最多索引前 12,000 字符，分成至多 1,200 字符的片段。页面展示最近 100 条片段，检索可查更早已经索引的内容。
- 没有被本项目接收的旧微信消息不在自动记忆覆盖范围；不会从其他安装目录自动搬运聊天和记忆。

资料保留原话、来源人物、聊天时间。模型应区分“当时说了什么”和“今天仍然如此”，不能把问句、计划或转述当作已经发生的事实。没有证据应说明不确定。

## 查看、私密与移出

主人某条话不想用于其他私聊时，开头写“【私密】”。包含明显密码、验证码、API Key 等标记的原话也会默认限制。自动检测只是补充；需要明确保留的内容请使用私密标记。

已收录后，可以在页面点击“设为私密”：同一原消息的所有片段都会限制。联系人自己的原话即使设为私密，仍可供本人和主人回忆；“私密”不会授予其他联系人的访问权。

“移出记忆”让该消息的全部片段不再参与跨聊天检索，保留原始档案；游标不会因重启而重复收录它。修改会更新记忆版本，使下一轮切换上下文，已经使用旧版本的在途回答会被拦截。已经发出的内容不会撤回。

关闭主人分享开关后，联系人只读自己的资料，主人仍可读各联系人。关闭自动聊天记忆后停止自动收录与回忆，已有资料保留在本机。重新绑定主人会隔离旧绑定下的自动资料，不向新主人重新导入绑定前的旧档案。

## 费用

收录、权限过滤与关键词检索都在本地完成，不额外调用 DeepSeek 做每句摘要或向量化。每轮只带入少量相关片段，自动上下文正文约 2,200 字符预算；按需记忆工具最多返回六条片段。正常模型回答和必要的工具续答仍按 DSH 的模型用量计费。
