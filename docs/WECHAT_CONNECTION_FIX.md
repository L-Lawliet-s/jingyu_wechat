# 微信首次连接修复与验证

修复日期：2026-10-26。

## 修复内容

- 源码桌面之前跳过了安装版才执行的配置准备，可能在首次连接时缺少本机发送令牌。现在两种启动方式都会初始化配置；连接前也会确保令牌存在，已有有效令牌不更换。
- 新源码目录没有匹配微信、发送 DLL 和自动连接 DLL 时，可从现有安装版的原始程序资源中校验并准备组件。导入仅涉及程序资源，不导入旧账号、聊天、令牌或读取凭据。
- 匹配微信要求 4.1.10.27 且腾讯签名有效，原生发送组件要通过版本和摘要校验。其他版本的普通微信不会被当成已连接，也不会被程序强制停止。
- 一键连接按“准备组件 → 核对发送端 → 必要时打开匹配微信 → 验证数据库 → 再次核对账号 → 保存”执行。错误账号、账号歧义或设置在过程中改变时仍拒绝保存。
- 自动查找默认目录之外的数据时，补充现有配置中的目录位置作为线索；旧密钥和旧账号选择不传入新连接请求。
- 自动导入只可替换项目专用客户端目录，不能替换用户设置或人格目录；更新失败保留旧组件。
- 概览分开展示“账号配置已验证”和“后台服务已运行”，避免服务未启动时错误提示用户重新连接微信。

## 实机结果

本机已经实际完成：

1. 从原始安装资源准备独立匹配客户端，验证程序与核心 DLL 的版本和腾讯签名。
2. 打开匹配微信，原生发送端初始化及本机认证健康检查通过。
3. 用户手动登录小号，实时账号核对通过。
4. 自动找到相应数据目录，用户按首次验证提示重新登录，数据库验证通过。
5. 新读取凭据以 Windows 当前用户加密保存，桌面记录显示已验证。
6. 独立读取检查确认数据库和联系人索引可读；更新并重开桌面后，通过桌面接口再次执行读取检查，结果成功。
7. 再次重开管理程序后，已验证状态保留，四项组件全部就绪；概览正确区分“账号已验证”和“服务尚未启动”。

没有发送测试消息，没有启动自动回复，没有复制旧读取密钥或聊天数据库。当前允许的聊天仍由用户配置；连接验证成功不等于已启动模型对话服务。

## 用户需要做什么

如果已经更新程序，先看首次配置中的组件是否全部已准备、读取配置是否已验证。使用项目专用微信并保持登录。

需要开始聊天时，再确认 DSH 插件属于当前开发目录，添加允许的私聊或群聊，保存并启动服务。只想测试大号时，允许范围只添加大号。
